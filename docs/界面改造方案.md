# ChatGPT Relay 界面改造方案

2026-11-09。目标：让眼镜上看得到对话上下文，交互接近现代 chatbot 和 coding agent（Claude Code、Codex 一类）的体验。本文只是方案，代码还没改。

## 一、现在的界面

### 眼镜（`plugin/src/main.ts`）

整屏只有一个 576×288 的文字框，第一行是状态，下面 9 行是正文：

```
reply 2/5 · swipe                        ← 状态行
今天下午三点的会议主要讨论三件事：         ← 最近一次回复的第 2 页
1. 眼镜项目进度……
……
```

| 操作 | 行为 |
|---|---|
| 单击 | 开始说话；说话中再单击就发送；出错后重试 |
| 按住 | 按住说话，松开就发送 |
| 上滑/下滑 | 回复翻页 |
| 双击 | 退出插件 |

问题：

1. **没有上下文。** `startTalk()` 会清空 `transcript` 和 `reply`，每一轮只保留最后一问一答。等回复时还能看到"你：……"，回复一到就只剩回复。往回翻看不到上一轮。
2. **状态信息太少。** 状态行是英文短语（`listening 3.2 s`、`sent · waiting for reply…`），看不出 ChatGPT 是在思考还是在输出，也不知道回复有多长、还剩多少。
3. **整屏重绘。** 状态和正文在同一个文字框里，计时器每 500 ms 刷新一次，就要把整屏文字通过蓝牙重发一遍。流式输出时也是整段重发。
4. **没有对话管理。** 不能开新对话，不能回到旧对话，只能在手机上手动操作 chatgpt.com。
5. **重开插件是空白。** 插件没有保存任何东西，退出再进只显示 `connecting…`。
6. **双击直接退出，容易误触，而且占用了一个很好用的手势。**

### 手机

- **Even App 里的插件页面**（`plugin/index.html`）只有一句"running. Check the glasses display."，什么都看不到。
- **G2 Relay App**（`MainActivity.kt`）是一行状态文字、三个按钮（后台运行、重载、退出），下面是完整的 chatgpt.com 页面。上下文在这里看得到，但这是 ChatGPT 自己的网页，和眼镜上的那一轮没有对应关系，状态行也只是一段文字。

## 二、能用的界面能力（Even Hub SDK 0.0.16）

| 能力 | 说明 | 对改造的用处 |
|---|---|---|
| 多个容器 | 一页最多 12 个容器，其中文字框最多 8 个、图片最多 4 个 | 状态栏、正文、提示行拆开，各自刷新 |
| 文字亮度 `textColor` 0–4 | 每个文字框一个亮度 | 状态和提示调暗，正文最亮，形成层次 |
| 局部更新 `contentOffset` / `contentLength` | 只改文字框里的一段 | 原想用于流式输出；实测固件不支持，见下面实验 6 |
| 列表容器 `ListContainerProperty` | 系统原生列表，滑动移动选中项，单击上报 `List_ItemEvent` | 对话列表、轮次目录、菜单页 |
| 上下文菜单 `menuObject` | 最多 10 项，每项最多 32 字节，点击上报 `menuItemClickEvent` | 原想用于操作菜单；实测在眼镜上打不开，见实验 6 |
| `rebuildPageContainer` | 整页换布局 | 在"对话""目录""菜单"几个视图之间切换 |
| `setLocalStorage` / `getLocalStorage` | 插件的本地存储 | 重开插件时先显示上次的对话 |

### 实验 6：真机实测（2026-11-09）

测试环境：Galaxy Z Fold5（Android 14）、Even App 2.4.0、SDK 0.0.16，插件从 Mac 的开发服务器加载。每一项都先在模拟器跑过，再在眼镜上测。

| 项目 | 眼镜上的结果 | 结论 |
|---|---|---|
| 亮度 0–4 | 五档都看得见，相邻两档能分清 | 状态栏和提示行可以调暗 |
| 三个文字框 | 计时器单独刷新，每次不超过 42 ms，正文不闪，层次清楚 | 三段式布局可行 |
| 局部追加 `contentOffset` | 按字符算偏移和按字节算偏移都一样：只显示最后一段 | **不能用**，固件忽略偏移，直接整段替换 |
| 整段重发 | 每次约 75 ms，文字正确、流畅 | 流式输出改为每次重发正文框 |
| 单框容量 | 更新：约 2000 字节以内成功（约 666 个汉字），2864 字节失败。新建和重建页面：716 字节成功，1432 字节失败，失败前要等约 2 秒。模拟器里两者都是约 1000 字节 | 正文只发当前看得到的一屏 |
| 框内滚动 | 内容超过一屏时，固件自己在框里滚动，到头时上报 `SCROLL_TOP` / `SCROLL_BOTTOM` | 内容控制在一屏以内，翻页由插件处理（现在就是这样做的） |
| 系统列表 | 滑动由固件移动选中项，不上报；单击上报选中项的序号。第一项的序号不出现在事件里（`undefined`），要当作 0 | 可用，但要处理第一项的序号 |
| 上下文菜单 | 双击、长按、单击都打不开 | **不能用**，改用自己做的菜单页 |
| 符号 | 你看到的全部显示正常。模拟器里有十几个缺字（✓ ▸ ► ✕ ⏎ ⚠ ┄ 等） | 真机可以用；但模拟器预览会显示空白 |
| 触控来源 | 右镜腿是 1，左镜腿是 3；没有收到 R1 戒指的事件 | 两侧镜腿都能用；戒指不能用 |

## 三、改造方案：眼镜端

### 1. 页面布局：三段式

```
┌──────────────────────────────────────────────┐
│ ● 对话 · 第 3 轮 · 输出中 4.1s          ↓  │ ← 状态栏，亮度 2，单独刷新
├──────────────────────────────────────────────┤
│ › 明天的会要准备什么                         │ ← 你说的话：前面加 ›，单独一行
│ 主要准备三样东西：                           │ ← 回复
│ 1. 上周的测试数据……                         │
│ 2. ……                                       │
│ ……                                          │
├──────────────────────────────────────────────┤
│ 单击说话 · 滑动翻看 · 双击菜单               │ ← 提示行，亮度 1，跟随状态变化
└──────────────────────────────────────────────┘
```

- 状态栏、正文、提示行分成三个文字框。计时器只刷新状态栏那一小段，正文不动。
- 一个文字框只能有一个亮度，所以正文里"你说的"和"回复"用符号区分：用户的话前面加 `›`，前后各空一行，回复不加。
- 状态栏右侧的 `↓` 表示下面还有新内容，没有就不显示。

### 2. 正文是整段对话，不再只显示一轮

做法和终端、coding agent 的滚动记录一样：

- 新一轮直接接在下面，不清空。本次插件运行期间的所有轮次都在一个可滚动的记录里，上滑可以一直翻到第一轮。
- **贴底跟随。** 回复流式输出时，如果你停在最底部，画面跟着新内容走；如果你已经往上翻，就不跳走，只在状态栏亮起 `↓`。下次按"说话"或滑到底时恢复跟随。
- **翻页的单位是行，不是"回复页"。** 每次滑动移动大半屏，保留 2 行重叠，翻页时不会丢位置。
- **只发看得到的一屏。** 整段对话存在插件里，每次只把当前一屏（约 9 行，几百字节）写进正文框。这样内容不会超出框，固件也不会自己滚动，滑动统一由插件翻页。
- 流式输出时每次重发这一屏，实测约 75 ms 一次，不闪。固件不支持局部追加。

### 3. 状态要看得懂（借鉴 coding agent）

| 阶段 | 状态栏 | 正文 |
|---|---|---|
| 空闲 | `● 对话 · 第 3 轮` | 停在上次看到的位置 |
| 听写 | `◉ 听写 12s · 单击发送` | 底部出现 `› …` 占位行 |
| 转写 | `◌ 转写中` | — |
| 已发出 | `◌ 等待回复 2.3s` | `› 明天的会要准备什么`（立即显示 ChatGPT 认出的文字，方便你核对） |
| 输出中 | `▸ 输出中 4.1s · 186 字` | 回复逐步出现 |
| 完成 | `✓ 第 3 轮 · 412 字 · 6.8s` | — |
| 出错 | `✕ 听写没启动 · 单击重试` | 错误原因一行，不清掉之前的对话 |

状态栏全部改成中文，加上耗时和字数，你一眼就能分清是"还在想"还是"卡住了"。

### 4. 发送前核对（可选）

现在 ChatGPT 听写完就自动发送。可以加一个"发送前核对"模式（在设置里开关）：

- 认出的文字先显示在 `› ` 行，状态栏显示 `单击发送 · 双击丢弃 · 3s 后自动发送`；
- 3 秒内不操作就照常发送，所以默认体验不变；
- 页面端已经有 `autoSend` 开关，只需要补"等眼镜确认再发送"这一步。

### 5. 两层视图：对话记录和轮次目录

回复长的时候，一直滑很累。仿照 coding agent 把每一步折叠成一行的做法，加一个目录视图：

```
┌──────────────────────────────────────────────┐
│ 本次对话 · 5 轮                              │
│   1 › 帮我想个周报标题            ✓ 2 屏    │
│   2 › 下午会议时间改到几点        ✓ 1 屏    │
│ ▶ 3 › 明天的会要准备什么          ✓ 6 屏    │ ← 系统列表的选中项
│   4 › 把第二点展开说说            ✓ 9 屏    │
│   5 › 总结成三句话                ▸ 输出中   │
└──────────────────────────────────────────────┘
```

- 用系统列表容器实现，滑动选中，单击跳回对话记录里那一轮的开头。
- 从菜单进入，也可以在对话记录里滑到最顶端再上滑进入。

### 6. 对话管理

页面端补三个动作，都是操作 chatgpt.com 自己的界面，不涉及 API：

| 动作 | 页面端怎么做 |
|---|---|
| 新对话 | 点侧栏的"新聊天" |
| 最近对话 | 读侧栏前 10 条对话的标题和链接，发给眼镜，用列表显示 |
| 打开某个对话 | 跳转到那个对话的链接，再把整段对话读出来发给眼镜 |

打开旧对话后，眼镜上看到的就是 ChatGPT 网页里的完整上下文，接着说话就是在这个对话里继续。

### 7. 菜单和手势

新的手势分配：

| 操作 | 行为 |
|---|---|
| 单击 | 说话 / 发送（和现在一样） |
| 按住 | 按住说话（和现在一样） |
| 上滑/下滑 | 滚动对话记录；在列表里移动选中项 |
| 双击 | 打开菜单（不再直接退出） |

菜单项（不超过 10 项）：

1. 新对话
2. 最近对话
3. 本次对话目录
4. 重新生成
5. 停止输出
6. 跳到最新
7. 设置
8. 退出

实测系统上下文菜单在眼镜上打不开，所以菜单做成一个列表页面：双击后整页换成系统列表，滑动选择、单击执行，再双击返回。列表最多显示约 6 行，菜单项按常用程度排序。

### 8. 重开插件不再是空白

- 每轮结束后，把当前对话的最近若干轮存进插件本地存储，重开插件时先显示出来，状态栏标 `(离线缓存)`。
- 插件连上 G2 Relay 后，页面端主动发一次当前对话的完整记录，用它替换缓存。
- G2 Relay 的页面重载后也发一次，眼镜就不会和网页对不上。

### 9. 长回复的显示

- 保留现在 `glasses-text.js` 把 Markdown 转成纯文字的做法。
- 代码块前后加一行 `┄┄ 代码 ┄┄` 作分隔，代码不自动换行缩进。
- 可选的"眼镜模式"：发消息时在前面带一段很短的说明，让 ChatGPT 先给三句话的结论再展开。默认关闭，因为它会写进对话记录。

## 四、改造方案：手机端

### Even App 里的插件页面

现在是空的，可以做成眼镜的"副屏"：

- 和眼镜同步的完整对话，带 Markdown 排版（代码块、列表、表格），自动滚到最新；
- 顶部一条状态（连接、听写、输出中），和眼镜的状态栏一致；
- 底部几个按钮：新对话、最近对话、停止输出；
- 可选：一个输入框，用手机打字发给 ChatGPT（走同一个 WebSocket，页面端把文字填进输入框再发送）。

插件页面本来就收到所有消息，加这个只需要在 `index.html` 里写界面，不影响眼镜端。

### G2 Relay App

主要价值是登录和后台保活，不需要大改：

- 状态栏改成三个小标签：眼镜（已连接/未连接）、chatgpt.com（已登录/未登录/页面没加载）、后台（已豁免/未豁免）。点未就绪的标签直接去处理，比如去登录或者打开电池豁免设置。
- 加一个"设置"页：发送前核对、最长说话时间、眼镜模式、按钮文字匹配规则（现在只能从 Mac 用 `{t: "config"}` 修改）。
- chatgpt.com 页面保持原样。

## 五、需要的协议改动

现有消息不变，新增以下几条。

页面发给眼镜：

| 消息 | 内容 |
|---|---|
| `{t: "history", chat, title, turns: [{n, user, reply, done}]}` | 当前对话的完整记录，在连接、重载、切换对话时发送 |
| `{t: "chats", items: [{id, title}]}` | 最近对话列表 |
| `{t: "turn", n, user}` | 新一轮开始，带上 ChatGPT 认出的文字 |

现有的 `reply` 消息已经带轮次号 `n`，继续用。

眼镜发给页面：

| 消息 | 动作 |
|---|---|
| `{t: "new-chat"}` | 新对话 |
| `{t: "list-chats"}` | 请求最近对话列表 |
| `{t: "open-chat", id}` | 打开某个对话 |
| `{t: "regenerate"}` | 重新生成 |
| `{t: "stop-reply"}` | 停止输出 |
| `{t: "confirm-send"}` / `{t: "discard"}` | 发送前核对模式下的确认或丢弃 |
| `{t: "get-history"}` | 请求当前对话的完整记录 |

页面端读取历史时复用 `reply-watch.js` 的选择器：`SEL.user` 和 `SEL.assistant` 已经能取出每一轮，再交给 `glasses-text.js` 转成纯文字。

## 六、分阶段

| 阶段 | 内容 | 改动范围 | 体验变化 |
|---|---|---|---|
| **1** | 三段式布局；整段对话的滚动记录（贴底跟随、↓ 提示、只发当前一屏）；中文状态栏；`history` 同步和本地缓存；双击打开列表菜单（先只放"新对话"和"退出"） | 插件 `main.ts`，页面端 `relay-main.js` 加 `history` 和 `new-chat` | 能看到上下文，这是最主要的痛点 |
| **2** | 轮次目录；最近对话和打开旧对话；完整菜单；停止输出和重新生成 | 插件加列表视图，页面端加侧栏读取和跳转 | 能管理对话 |
| **3** | 发送前核对；Even App 里的插件副屏；G2 Relay 状态标签和设置页 | 插件 `index.html`，`MainActivity.kt` | 手机上也有好用的界面 |

阶段 1 开工前的眼镜实验已经做完（见第二节"实验 6"），方案已按结果调整：

- 不用局部追加，改为每次重发当前一屏；
- 不用系统上下文菜单，改用列表页面做菜单；
- 正文只放一屏的内容。

## 七、阶段 1 实施记录（2026-11-09）

插件 0.2.1、G2 Relay 0.2.4（内置扩展 0.6.4）。先用 `tools/fake_relay.py` 在模拟器里调好界面，再在 Galaxy Z Fold5 上实测，三段式布局、历史同步、流式回复、翻页、菜单和新对话都已在真机上用过。真机上踩到的坑：

- **新对话按钮在收起的侧栏里**：手机窄屏时侧栏收起，按钮找不到。只用 `history.pushState` 改网址不行：网址变了，React 不切换对话，之后听写落不到输入框。现在先点"显示侧边栏"再点"新聊天"，找不到就报错。
- **切换对话后旧对话藏在页面里**：实测页面上有 3 个输入框（2 个隐藏）、8 条消息只有 2 条可见。输入框和历史只认可见元素（`getClientRects()` 非空）。
- **残留草稿**：失败的听写会在输入框留下文字，ChatGPT 还会保存成草稿，下一次会一起发出去。开始听写前先清空输入框。
- **太短的录音**：快速点两下（或双击被拆成两次单击）只录到 0.1 秒左右，转写为空。插件把短于 0.8 秒的说话当作取消。
- **迟到的报错**：上一轮还在等转写时开始新一轮，旧一轮超时报错会打断新一轮。页面端给每轮编号，丢掉旧轮的结果。
